# L4a 系统对象初始化：待确认的安装行为

日期：2026-09-16。状态：**设计提案，尚未安装计划任务或开机组件。**
后续约定以[长期授权与目录分区](./standing-permissions-l4a.md)为准：默认不安装开机项；
只有用户显式选择后才准备一次触发的固定任务。下面保留原始提案及其证据，不作为默认安装授权。
这是对[原 L4a 计划](./windows-permissions-l4a.md)中“一次受控初始化、日常不提权”的具体补充。
代码和 native 原始证据见[当前验收记录](../acceptance/windows-lpac-p1-0.2.3.md)。

## 1. 已证实的问题

Git 在 LPAC 中必须取得 DOS/卷路径映射。本机实验中，给五个固定 NT 对象添加专用能力的
查询 ACE 后，Git show/config/diff 成功，A 只读、B 可修改、C 不可读和回环禁网仍成立。
这些 ACE 已在实验结束后移除并核实；业务目录没有被扩大授权。

但修改 NT 对象的当前 DACL 不是永久安装配置。微软说明：卷链接及目标设备对象不在重启后
保留，Mount Manager 通过注册表中的名称记录重建它们。因此不能从一次临时实验推断查询 ACE
会在下次开机仍然存在。[Microsoft Mount Manager 说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/storage/supporting-mount-manager-requests-in-a-storage-class-driver)

尚未重启用户电脑实测；本轮不擅自重启、开 Developer Mode、安装服务或添加开机任务。
现有 `probe-lpac-namespace-admin.py` 只为一次实验准备权限，十分钟内清理，不能直接作为安装器。

## 2. 建议确认的方案

允许 `agenthub sandbox setup` 安装一个**每次开机运行一次、完成后立即退出**的 Windows 计划任务：

- 名称：`\AgentHub\SandboxInitialize`；使用 SYSTEM，启动时触发，最长运行 30 秒。
- 仅执行安装到受保护位置的固定初始化程序，使用受保护的对象清单。
- 只维护已验证的系统命名空间查询 ACE；不接触业务目录 ACL、会话、凭据、记忆或模型请求。
- 不接受 CLI、文件 worker 或模型提供的命令、脚本、程序路径和对象路径；没有命令执行代理接口。
- 不常驻，不监听 IPC/网络，不执行项目代码。日常 Run 继续使用普通用户宿主和独立 LPAC 身份。

原计划没有具体约定开机计划任务。这是新增的系统安装行为，需要用户确认后再实现并安装；
不能把已确认的一次临时 UAC 预检解释为已批准任意持久化入口。

另一可行取舍是每次重启后由用户手动执行管理员初始化，但这会增加重复 UAC 操作。
不建议把初始化放到每个 Run，更不能因初始化缺失就降级为当前用户执行。

## 3. 固定安装范围和保护

| 位置 | 内容和权限 |
| --- | --- |
| `%ProgramFiles%\AgentHub\Sandbox\<版本>` | 经过核对的初始化脚本、固定 Python/pywin32 依赖；仅管理员和 SYSTEM 可写 |
| `%ProgramData%\AgentHub\Sandbox` | 管理员维护的对象清单、安装/清理意图和诊断；普通用户只读必要状态 |
| Windows Task Scheduler 的上述任务 | 固定绝对程序/参数；普通用户不能修改执行动作、账户或触发器 |

安装清单不得引用用户可写的 venv、源码目录、`.agenthub`、项目文件或临时下载路径。
管理员 helper 不从当前目录、用户 site-packages、PATH 或用户环境加载代码；部署的解释器和
依赖需要明确清单、哈希与 DLL 搜索路径保护。首次安装、替换该受保护组件或更改系统对象清单
仍是明确的管理员管理操作，不在普通聊天里自动发生。

系统查询 capability 使用安装级稳定名称；它只对应系统路径查询，不对应业务目录。
业务目录 ACE 继续使用每个 Run 独立 SID，不能用安装级 capability 合并不同 Run 的资源范围。
初版只允许枚举并确认的本地盘符。新磁盘或对象发生变化时，doctor 给出缺项，用户重新初始化；
后台任务不扫描个人目录、不自动增加文件许可。

## 4. 生命周期与失败处理

1. `setup` 显示实际目录、依赖清单、任务名称、对象掩码及系统账户；用户确认 UAC 后才部署。
2. 初始化打开全部固定对象、核对现状并保存意图，再逐项应用和读回核实。失败只补偿本工具 ACE。
3. 开机任务按同一固定清单幂等处理；短暂等待挂载有总时限，失败后退出并保存诊断，不无限重试。
4. CLI 准备受限 Run 时只读检查实际对象/策略和初始化状态；旧的“成功”文件不能代替当前核实。
5. 缺项、保护不合格或遗留清理状态均拒绝受限执行，不切回普通令牌。
6. `repair` 只处理登记的对象与本工具 ACE。卸载先确认无活动 Run，再移除计划任务及本工具 ACE；
   不恢复旧完整 DACL，不修改所有者，不删除其他程序的 ACE。

管理员初始化与 SQLite 仍不是跨系统原子事务。系统对象变动、重启、升级失败和卸载过程必须有
可重复的补偿与诊断；没有实现这些步骤前不对外称 `sandbox setup` 已完成。

## 5. 实施与放行门槛

确认方案后，先实现受保护组件与安装/卸载原型，再进入以下本机验证：

- 普通用户不能替换 helper、清单、解释器、DLL 或计划任务动作；篡改导致明确拒绝。
- 开机初始化有界且只处理固定清单；失败不启动工具、不改变业务许可。
- 重启前后都核实实际 ACE、Git 正对照和 A/B/C 拒绝，不能只看计划任务退出码。
- 管理员仅创建隔离测试中的符号链接夹具，然后由普通用户运行 LPAC 访问测试。
- 补齐嵌套 Job、ACL 清理失败、初始化中断及恢复；不依赖时间戳推断进程死亡。
- 查询型系统权限不能用于修改挂载关系；在隔离环境中验证相关写操作被拒绝。
