## 1. 产品约定

- 用户一次选择广泛范围，可以包括工作盘和常用资料目录，不自动授权全部用户文件。
- 新受限任务默认继承长期权限；cwd 仅决定相对路径，必须可读。跨目录不重复询问已授权范围。
- 可修改工作区、只读资料区分别授权；私人资料位于授权范围外。用户自行整理和移动资料。
- 不在可修改根内实现只读/禁止访问例外，不自动搬移、复制或删除用户文件。
- “此前可修改、此后不可修改”由用户明确发起权限转换；先确认相关执行全部退出，再撤销旧身份。
- 不承诺用户在资源管理器中移动文件就立即撤权，不实现实时移动监视或后台自动封存。
- Windows 移动可能保留对象 ACL；未先撤权就移动的对象不能仅按新路径宣称已保护。
- 任务本身只能收窄权限；每个任务仍使用独立的有效策略身份，不携带完整长期策略的额外权限。
- 本期没有临时放行、工具联网、GUI 自动化、常驻服务、多助手或 Rust 迁移。
- 当前用户始终登录电脑；可信宿主管理模型连接、凭据和状态，模型触发的本机操作全部受限。
- 旧任务保留原模式；只有显式 `--sandbox windows` 才转换。旧 trust 不转换成新许可。
- `current-user` 仅作为用户显式选择；要求受限执行却无法满足时拒绝运行，不自动回退。
- 记忆和资源元数据复用仍独立于文件授权，撤销目录不自动遗忘已批准记忆。

## 2. 策略计算与身份

基础授权为规范化目录与 read/modify；保护规则为 read/deny；系统保护由宿主提供。
基础授权取覆盖路径的许可并集，保护取最严格限制，再与任务选择求交。
更深的普通授权不能覆盖保护区；系统状态、凭据、权限配置和可信控制组件不能交给工具修改。
modify 包含业务内容的读、创建、修改、重命名和删除，不包括修改 DACL、所有者或隔离规则。

计算后必须验证能否通过自然继承落实。`inheritable_roots` 生成仅增加权限的根集合；
`freeze_policy` 在发放快照前完成校验。`permission_layout_conflict` 表示子区域比父授权更窄，
应提示移出资料或缩小上层授权，不能静默忽略规则或发布看似安全的快照。

```text
D:\Work       modify
D:\Archive    read
D:\Private    未授权
```

以上布局可用；若改为 `D:\Work\Archive=read`，同时 `D:\Work=modify`，则拒绝准备。
同理，整盘授权包含状态目录或其他必须禁止访问的内容时不能默默挖洞，应缩小授权范围。
只读父目录加可修改子目录属于自然增加权限，可以表达；重复授权合并，不授予安全管理权限。
若整个授权根被改为只读，可以直接编译成只读根；不需要停止其 Windows 继承。
自定义任务也可以只选择不含冲突的目录，或者将所选整个范围收窄为只读。

新契约位于 `agent_contracts.permissions`；规则计算位于 workspaces 的 permissions 模块。
契约是不可变数据，算法不访问文件系统，不修改 ACL，不构成 OS 隔离证明。
适配器负责真实路径、NTFS、对象身份、链接与当前权限核实；模型不能提供身份或批准状态。

- `StandingPermissionPolicy`：环境/助手绑定、修订、授权、保护和启用状态。
- `TaskPermissionSelection`：inherit 或 custom；后者必须明确列出不超过长期许可的根。
- `ExecutionPolicySnapshot`：冻结规则及确定性摘要；本期 network 固定 deny。
- `PermissionLeasePort`、`ExecutionIsolationPort`、`FileOperationsPort`：原生门槛后接入。

每个 Run 独立 Package SID、Job、临时目录和租约；每个不可变有效策略独立业务 capability SID。
相同有效策略复用已准备的权限，不同范围不能共享通行身份。收窄任务不能携带完整长期策略 SID。
规则改变生成新策略身份，不原地扩张活动进程权限；系统查询 capability 与业务权限严格分离。

用户已确认首版只在同一 CLI 进程内复用，跨进程和重启重新准备并生成新业务身份。
规则摘要不等于可永久使用的 capability：同一规则也可因对象移动或准备失效而产生新代际。
进程内 `PreparedPolicy` 已实现准备、登记、忙时拒绝停用、确认退出、永久停用和待修复状态。
其后端目前仅为新建测试树使用；正式 NTFS 准备器、持久化修复及宿主接入仍待实现。
原型证明即使根对象未变，移走的后代仍可能携带旧 ACE；仅缩短缓存存活时间不构成隔离证明。
本期通过先撤销旧身份再整理文件来落实用户明确发起的转换，不用目录监视冒充撤权。

首次准备可遍历用户选择的树，只检查对象与 ACL，不读取正文、不建立全盘资源索引。
准备可取消并记录实际进度；未完成不能启用。复用核实授权根、边界、依赖与清理状态，不能只信缓存。
当前夹具增加隔离工具副本的完整 SHA-256/对象清单复核，缺失、替换、新增及路径别名使实例失效。
该检查在每次登记前运行，不是实时文件监视；正式准备器的持久化修复和跨宿主恢复仍待实现。

### 显式撤权的顺序

1. 宿主停止接收该准备实例的新执行；本期权限修改要求相关任务空闲。
2. 有活动执行时先通过现有取消路径停止，驱动确认 Job 已清空后才释放登记。
3. 移除并核实旧业务身份的自有 ACE。失败保留待修复状态，不能报告已封存或启用替代身份。
4. 旧准备实例永久停用。用户可以移动资料；新策略使用新的 capability，不原地复活旧实例。
5. 新权限准备及原生检查通过后才允许继续任务。权限失败不回退为普通用户进程。

已有协调器对活动登记返回 `permission_busy`，自身不终止进程；取消与驱动清理由可信宿主负责。
只有驱动确认退出才能调用 `finish(job_drained=True)`。未确认时保留登记，阻止 ACL 清理和重新使用。
该进程内接口不能独自证明其他 CLI 没有执行；跨宿主排他与持久化事务留待 P3，未完成前不公开管理命令。

## 3. 原生门槛

先用新建仓库内 NTFS 夹具证明独立的 Work 可修改、Archive 只读、Private 未授权。
测试不使用日常状态，不修改未知目录，不复用既有夹具。

- 文件、PowerShell 7、Python、Git、uv 和子进程均须满足相同边界，保留正对照。
- 覆盖父目录 DELETE_CHILD、授权根 DELETE/重命名、替换节点、修改 DACL 和所有者隐含权限。
- 具体访问位及 ACE 顺序不能误伤读取；已有对象、关闭继承对象和新建对象均须检查。
- 链接、junction、硬链接和备用路径不能绕过。授权/清理不跟随未知 reparse point。
- 不改变用户自身许可或以旧完整 DACL 回滚；先记录意图，仅移除本工具登记的 ACE。
- 策略复用、不同策略并行、私有临时目录、子进程与继承句柄必须验证无权限并集。
- 保留原先的禁网、Job、取消、宿主退出和初始化门槛；子集通过不能替代全部验收。

出现绕过即停止正式接入和发行，先修复并保留失败证据；不能用普通令牌、全权限代理或路径判断代替。
参考 [Microsoft 文件权限](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights)。

### 已发现的实现边界（2026-09-16）

广泛 capability ALLOW 加 DENY、以及只收窄自有 ALLOW 两种原型，均在 build 26200 出现保护区越权。
已保留实际成功的越权操作与失败报告；需求调整后，这些旧例外配置在纯策略阶段直接拒绝。

显式诊断选项 `inheritance-barrier` 在新建夹具中通过顺序复用、收窄与文件权限子集，但必须冻结
保护节点及必要祖先对**所有主体**的 ACL 继承。夹具已验证恢复；真实目录并发 ACL 修改时的安全补偿未实现。
用户决定通过目录布局处理归档隔离，因此不采用这一选项，不再要求用户接受继承副作用。
原型中仅为复现历史保留显式诊断选项，正式准备器不应接入它。
新的 `separate-roots` 默认原生子集已通过；原启动结构的完整软件链已有初始化后通过记录。
后续新增并行策略、依赖异常和嵌套 Job 子集通过；用户重新确认 UAC 后，新结构完整软件链和
真实符号链接也已通过。汇总在确认初始化清理后记录 `gate=passed`，原未执行证据继续保留。
后续移动门槛在两个独立夹具中复现旧 capability 对移入 Private 的文件/目录读写，
以及对移入 Archive 的文件写入。换新 capability 的对照通过，但不等于已实现安全失效流程。
新增显式门槛测试保留失败；不以 95 项证据/策略单测通过掩盖原生失败。
后续明确改变了产品时序：停止全部相关 Job，核实旧身份撤权，然后由用户整理资料。
新的原生子集验证旧身份再次直接访问也被 OS 拒绝，并验证新只读身份；不将旧移动试验追溯改为通过。

## 4. 待接入的用户入口与执行链

`permissions setup` 选择范围和保护；grant/protect/unprotect/revoke 修改规则；check 解释结果。
保存与准备前解释布局冲突，用户调整目录或上层授权后再提交；系统不代为移动资料。
脚本修改要求 `--revision N`，交互入口读取并提交 CAS。管理不需要模型凭据。
`permissions` 和 `/permissions` 显示模式、来源、修订与准备状态。
`--permissions inherit` 为默认；custom 配合 `--read-dir` / `--write-dir` 主动收窄。
继承模式中 add-dir 不重复询问范围内目录；范围外提示管理命令，不自动扩权。
执行期间没有审批弹窗；拒绝作为工具结果，用户空闲时调整规则后再次输入。

固定 JSON 文件 worker 承接所有模型触发的文件、忽略规则、Git 索引、资源探测和软件 hash。
宿主不能因模型参数绕过 worker 直接 stat/read/hash；无任意回调、pickle 或权限修改接口。
保留文件 hash 前置条件、编码/BOM/换行、命令参数数组、超时和有界输出。
PowerShell 5.1 未通过；受限模式不回退到它。软件启用状态及指纹仍须核实。

本期采用显式空闲转换，不实现后台即时撤权。管理入口先核实所有相关 Run 空闲，忙时返回具体任务；
用户取消后重试。执行登记与撤权须由 P3 的跨宿主排他机制串行化，避免检查空闲后又启动新 Run。
只有旧 Job、ACL 和身份清理已核实时才能提交“已撤权”；补偿失败保留待修复，不制造假成功。
成功事务、Context CAS、续接游标与 L2/L3 outbox 的原子语义保持，权限转换不伪造聊天 Run。
原先 Windows 事件通知与 250 ms 实时撤销轮询方案暂缓，不作为本期已实现能力。
