共享包/后端仍为 0.2.2，本地数据库仍为 v5。下面的 CLI、原生驱动和 v6 是待交付目标。

## 1. 产品约定

- 用户一次选择广泛范围，可以包括工作盘和常用资料目录，不自动授权全部用户文件。
- 新受限任务默认继承长期权限；cwd 仅决定相对路径，必须可读。跨目录不重复询问已授权范围。
- 保护区采用只读或禁止访问，任务本身只能收窄权限。用户通过管理入口修改长期规则。
- 本期没有临时放行、工具联网、GUI 自动化、常驻服务、多助手或 Rust 迁移。
- 当前用户始终登录电脑；可信宿主管理模型连接、凭据和状态，模型触发的本机操作全部受限。
- 旧任务保留原模式；只有显式 `--sandbox windows` 才转换。旧 trust 不转换成新许可。
- `current-user` 仅作为用户显式选择；要求受限执行却无法满足时拒绝运行，不自动回退。
- 记忆和资源元数据复用仍独立于文件授权，撤销目录不自动遗忘已批准记忆。

## 2. 策略计算与身份

基础授权为规范化目录与 read/modify；保护规则为 read/deny；系统保护由宿主提供。
基础授权取覆盖路径的许可并集，保护取最严格限制，再与任务选择求交。
更深的普通授权不能覆盖保护区；系统状态、凭据、权限配置和可信控制组件不能交给工具修改。
modify 包含业务内容的读、创建、修改、重命名和删除，不包括修改 DACL、所有者或隔离规则。

新契约位于 `agent_contracts.permissions`；规则计算位于 workspaces 的 permissions 模块。
契约是不可变数据，算法不访问文件系统，不修改 ACL，不构成 OS 隔离证明。
适配器负责真实路径、NTFS、对象身份、链接与当前权限核实；模型不能提供身份或批准状态。

- `StandingPermissionPolicy`：环境/助手绑定、修订、授权、保护和启用状态。
- `TaskPermissionSelection`：inherit 或 custom；后者必须明确列出不超过长期许可的根。
- `ExecutionPolicySnapshot`：冻结规则及确定性摘要；本期 network 固定 deny。
- `PermissionLeasePort`、`ExecutionIsolationPort`、`FileOperationsPort`：原生门槛后接入。

每个 Run 独立 Package SID、Job、临时目录和租约；每个不可变有效策略独立业务 capability SID。
相同有效策略复用已准备的权限，不同范围不能共享通行身份。收窄任务不能携带完整长期策略 SID。
规则改变生成新策略身份，不原地扩张活动进程权限；系统查询 capability 与业务权限严格分离。

首次准备可遍历用户选择的树，只检查对象与 ACL，不读取正文、不建立全盘资源索引。
准备可取消并记录实际进度；未完成不能启用。复用核实根、保护节点、依赖与清理状态，不能只信缓存。

## 3. 原生门槛

先用新建仓库内 NTFS 夹具证明 Work 可修改、Work/Archive 只读、Work/Private 禁止访问。
测试不使用日常状态，不修改未知目录，不复用既有夹具。

- 文件、PowerShell 7、Python、Git、uv 和子进程均须满足相同边界，保留正对照。
- 覆盖父目录 DELETE_CHILD、对象 DELETE、重命名祖先、替换节点、修改 DACL 和所有者隐含权限。
- 具体访问位及 ACE 顺序不能误伤读取；已有对象、关闭继承对象和新建对象均须检查。
- 链接、junction、硬链接和备用路径不能绕过。授权/清理不跟随未知 reparse point。
- 不改变用户自身许可或以旧完整 DACL 回滚；先记录意图，仅移除本工具登记的 ACE。
- 策略复用、不同策略并行、私有临时目录、子进程与继承句柄必须验证无权限并集。
- 保留原先的禁网、Job、取消、宿主退出和初始化门槛；子集通过不能替代全部验收。

出现绕过即停止正式接入和发行，先修复并保留失败证据；不能用普通令牌、全权限代理或路径判断代替。
参考 [Microsoft 文件权限](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights)。

### 已发现的实现边界（2026-09-16）

广泛 capability ALLOW 加 DENY、以及只收窄自有 ALLOW 两种原型，均在 build 26200 出现保护区越权。
已保留实际成功的越权操作与失败报告，默认原生门槛仍为失败，不继续正式接入。

显式诊断选项 `inheritance-barrier` 在新建夹具中通过顺序复用、收窄与文件权限子集，但必须冻结
保护节点及必要祖先对**所有主体**的 ACL 继承。夹具已验证恢复；真实目录并发 ACL 修改时的安全补偿未实现。
这一选项尚未纳入产品方案。采用前须确认该副作用，补充受影响节点清单、转换条目归属和冲突修复设计；
若要求保留其他主体的动态继承，则须继续研究原生方案。两者都不能用局部正例提前放行 P2。

## 4. 待接入的用户入口与执行链

`permissions setup` 选择范围和保护；grant/protect/unprotect/revoke 修改规则；check 解释结果。
脚本修改要求 `--revision N`，交互入口读取并提交 CAS。管理不需要模型凭据。
`permissions` 和 `/permissions` 显示模式、来源、修订与准备状态。
`--permissions inherit` 为默认；custom 配合 `--read-dir` / `--write-dir` 主动收窄。
继承模式中 add-dir 不重复询问范围内目录；范围外提示管理命令，不自动扩权。
执行期间没有审批弹窗；拒绝作为工具结果，用户空闲时调整规则后再次输入。

固定 JSON 文件 worker 承接所有模型触发的文件、忽略规则、Git 索引、资源探测和软件 hash。
宿主不能因模型参数绕过 worker 直接 stat/read/hash；无任意回调、pickle 或权限修改接口。
保留文件 hash 前置条件、编码/BOM/换行、命令参数数组、超时和有界输出。
PowerShell 5.1 未通过；受限模式不回退到它。软件启用状态及指纹仍须核实。

权限缩减事务提交后通知受影响 Run，取消模型请求、撤销租约并终止 Job。
每 Run Windows 事件用于唤醒；活动期间最多 250 ms 核对版本兜底，不调用模型。
无关修改不取消 Run，扩权只影响后续 Run。成功事务再次验证旧快照仍获允许，裁定完成/撤销竞争。
保留唯一终态、Context CAS、续接游标与 L2/L3 outbox；实际撤销延迟必须测量。

## 5. 初始化、存储和交付

setup/doctor/self-test/repair 增加卸载。固定受保护初始化组件只处理经过核对的系统查询对象。
默认没有开机项；缺项时用户手动准备。显式选择开机准备才安装一次触发、有界退出的固定任务。
组件不能执行项目/模型脚本或管理业务 ACL；部署前提供实际清单。普通升级不重启电脑或默装开机项。

v6 保存长期策略、保护、任务模式/选择、准备记录、租约、审计及清理状态。
v1–v5 直接升级沿用迁移锁、会话锁、SQLite backup API 和单事务；不生成授权、不改业务 ACL。
旧版拒绝 v6，回退使用旧 wheel 与升级前备份。Web 不新增无用途表，共享接口变化须回归。
