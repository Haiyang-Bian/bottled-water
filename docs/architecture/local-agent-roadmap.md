# 本机持续记忆：开发阶段与验收计划

> 状态：计划记录，L1–L4 均未实施、未验收。记录日期：2026-09-15。
> 实现基线：`agenthub-system 0.1.7`，源码 `d43f07ba954b74ea544815f4ba8a294766109f34`。
> 本文与[方向及详细设计](./local-agent-environment.md)配套。当前工作仅完成文档记录，不启动版本发布、迁移数据库或变更用户授权。

## 1. 交付目标与阶段关系

交付一个具有本机持续记忆的助手：从任意目录启动，能够找到旧工作、使用获准的相关知识、定位资料和软件，并在正确位置继续操作。任务仍有独立历史、预算、取消与运行记录。

| 阶段 | 交付重点 | 用户能够观察到的变化 | 当前状态 |
| --- | --- | --- | --- |
| L0 文档基线 | 方向、术语、职责、阶段与验收 | 设计和现状有明确区分 | 已记录，文档检查通过 |
| L1 任务与位置解耦 | 本机环境身份、全局任务发现、保存/切换工作位置 | 不记 ID、不先切目录也能继续旧工作 | 待实现 |
| L2 基础记忆闭环 | 记录、来源、检索、修正、遗忘与预算 | 新任务能使用旧知识，纠错后不再沿用旧结论 | 待实现 |
| L3 资源与工作连续性 | 资源目录、软件定位、自动积累已验证经验 | 找到旧实验的资料和工具，完成跨目录后续任务 | 待实现 |
| L4 共享与细粒度执行 | 多助手记忆共享、并发更新、权限驱动 | 共享知识但不扩大授权，冲突和拒绝可解释 | 待实现 |

依赖顺序为 L1 → L2 → L3 → L4。权限值类型和身份边界从 L1/L2 就要明确，但 L4 的完整驱动和多助手实现不成为前三阶段的前置。可在 L1–L3 独立验证 Windows 技术可行性，不能因此将未落实的隔离能力标为通过。

L1–L3 组成首个单助手产品闭环。L4 是后续扩展，单独验收；完整方向包含 L4，但不应让其复杂度阻止已通过的单助手版本交付。

本计划使用阶段编号，不立即修改发行版本。实施时确定对应的小版本，建议采用新的 `0.2.x` 系列以说明会话默认范围的变化；该建议不代表已经发布或预先创建标签。

## 2. L0：建立可追溯的设计基线

### 目的

明确“全局基础记忆”与“全局会话历史”的区别，确认工作目录从身份约束转为执行位置，记录与 0.1.7 的差异。

### 交付内容

- 方向及详细设计、本文开发计划。
- 总体架构、子系统目录、迁移说明、文档首页和当前状态的入口更新。
- 当前 CLI 行为仍按源码说明，新增能力明确为计划。
- 保存来源基线与文档参考日期，既有版本验收结论保持原样。

### 检查与完成条件

检查文档内部链接、代码路径、术语、阶段状态、Markdown 结构与 `git diff --check`。只提交文档改动，保留用户的 `frontend/pnpm-workspace.yaml`。L0 不运行模型、不生成新 wheel、不执行 schema 迁移，也不将文档检查记为功能验收。

## 3. L1：任务与工作位置解耦

### 3.1 目的与前置

建立用户的本机环境和稳定助手身份，使一个任务可以跨目录继续。保留现有锁、持久化和退出码，先完成可用的恢复流程。

实施前读取 `sessions.py`、`session_queries.py`、CLI 组装、路径接口及存储迁移；确认当前分支/发布基线，保护现有用户状态。新接口和用户行为变更应在本阶段同时更新调用方。

### 3.2 开发工作

1. 建立环境与拥有者绑定，单助手先提供一个默认身份。环境与 `AGENTHUB_HOME` 隔离；不扫描或合并其他用户/状态目录。
2. 将 session 的归属与 root 拆开；保留原 ID、创建位置及旧事件，增加保存的工作位置和版本。
3. 当前目录筛选改为显式选项；`-c` 与选择器共用按最近 Run 排序的本机候选规则，继续忽略空草稿。
4. 全局恢复仍检查环境/拥有者、锁及获准范围；不能只是删除目录检查后暴露所有记录。
5. 恢复采用任务保存的位置，启动位置只影响新任务。无效位置或授权不足时允许获准的只读查看，但执行必须先解决位置/授权问题。
6. 增加 `/cd` 和受控的位置接口；每次文件/进程调用传入位置快照，避免宿主全局 `os.chdir`。
7. 拆分 cwd 与资源授权；原信任记录精确保留，不因全局会话发现而扩展到父目录、整盘或全部资源。
8. 同一批调用的位置变更有确定顺序；位置事件、保存值与租约一致，迟到执行不能回写位置。
9. 更新帮助、普通/纯文本/JSONL 展示及升级说明，明确 `-c` 范围变化。批处理缺少位置或授权时返回可执行的错误说明。

### 3.3 模块与产物

主要涉及 `agent_cli` 的控制器/参数/选择器、存储查询和迁移、`workspaces` 的路径与位置接口、`execution`/工具的上下文传递。共享接口变化当版更新 Web 调用方，不复制循环。

产物包括迁移实现、目标行为说明、针对性测试、安装 wheel 与校验值、阶段验收记录。软件适配器和长期记忆尚不要求完成。

### 3.4 放行条件

- 从 B 目录启动，能通过无 ID 列表恢复 A 的任务，并在模型请求与工具记录中确认使用 A 保存的位置。
- A 的任务失败、取消或遗留 `running` 时仍能被正确发现；崩溃恢复仍先取得锁。
- 最近任务占用时返回会话占用，不自动选另一个；交互切换失败后原任务可继续。
- 新建/取消选择/只读浏览不产生影响排序的空会话。
- 中文、空格、链接目录、失效位置、两个同名任务及非 TTY 均有行为断言。
- 两个并行任务有独立 cwd；任务切换不修改另一个进程/工具的执行位置。
- 旧 v1/v2 状态升级后 ID、原上下文、信任、凭据引用与历史不丢失；隔离安装在仓库外复现恢复流程。

### 3.5 停止条件

若恢复会悄悄改用启动目录、扩大授权、丢失原会话锁，或跨环境显示不应出现的数据，本阶段不得放行。共享执行接口破坏 Web 核心聊天或取消时，先修复再交付。

## 4. L2：基础记忆的完整闭环

### 4.1 目的与前置

新任务能够使用过去积累的可靠知识，并支持修正和遗忘。依赖 L1 的环境身份；保持任务 scope 独立。

### 4.2 开发工作

1. 定义有类型的记录、修订、来源、有效性与可见性；区分用户声明、工具观察和模型推断。
2. 在现有 SQLite 适配器增加逻辑独立的记忆、修订、遗忘标记、处理任务和查询索引；接口不依赖 CLI 或 ORM。
3. 提供用户入口 `/memory` 及明确的记住、修正、停用、遗忘操作。列表可选择，不要求记 ID；浏览不初始化模型客户端。
4. 提供有界的模型查询/候选入口，身份与授权由宿主绑定；拒绝任意 SQL、跨环境读取和候选自授权限。
5. 接入 `LocalContextProvider` 和公共装配器：基础资料少量常驻，其他知识按任务检索，全部计入现有总预算。
6. 先实现名称、别名、主题、路径、时间和文本检索；中文短词提供有界回退或分词方案，不让正常查询误返回全表。
7. 保存使用清单，包括记忆修订、来源和装配诊断；下一次请求确实收到相关知识，而不只是数据库能够查出记录。
8. 明确写入结果；修正产生新版本，冲突保留来源，遗忘清除召回投影并阻止从旧来源自动再生。
9. 建立 Journal 到记忆处理的幂等路径；完成事务内登记待处理任务，执行/索引工作在事务外运行。
10. 保留已成功任务的终态；后续记忆整理故障单独显示、重试。失败 Run 的已确认事实可保存，未知操作不补写结果。

### 4.3 默认范围

先支持偏好、环境事实、工作决定和有证据的经验。使用结构化候选和确定性处理，不默认引入额外总结模型、向量数据库、自动清盘扫描或常驻后台进程。原始思考不进入记忆记录。

### 4.4 放行条件

- 在 A 保存偏好/事实，新建 B 的任务后下一次模型请求收到正确记录及来源，没有复制整个 A 会话。
- 用户的一次性要求没有变成全局偏好；项目事实不会错误覆盖另一个项目。
- 修正后新任务使用新版本，旧 Run 的使用清单仍指向旧版本。
- 遗忘后检索不到；重启和重复整理原日志不会恢复它。保留日志与物理删除的边界在界面可见。
- 大量记忆不会挤掉当前请求、突破预算或破坏工具消息配对；无结果、失效记录、相似候选得到明确处理。
- 非授权记录的正文、标题、结果计数和错误详情均不泄露；外部文件中的恶意指令不能成为全局规则。
- 候选落盘、Run 完成、记忆修订、处理游标及索引更新各边界注入故障；重启后无重复记忆、无假成功、无丢失的待处理事实。
- 查看/修正/检索无须模型凭据；显式记忆保存失败不能回答“已经记住”。

### 4.5 停止条件

若记忆读取变成全历史拼接、无来源结论被当成事实、遗忘会自动再生，或记忆整理破坏既有终态原子性，不得放行。索引存在但实际模型输入未使用记忆不算完成。

## 5. L3：资源、软件与跨任务工作连续性

### 5.1 目的与前置

把基础记忆转化为能够继续实际工作的能力。依赖 L2 的来源、修订和检索，软件调用仍使用已有工具执行链。

### 5.2 开发工作

1. 建立资源目录，支持项目、数据、产物、目录和已接入软件的稳定 ID、名称/别名及关联。
2. 从用户登记、已确认工具结果和明确范围索引积累信息；提供索引范围/时间/覆盖状态。
3. 记录软件可执行路径、版本、参数用法和配置引用；调用前核实，不能执行记忆中未经验证的任意脚本。
4. 建立自然语言旧任务检索，将“昨天的实验”等表达映射到有来源候选；歧义由列表解决。
5. 关联任务进展、结果资源和下一步；复用失败续接处理未知操作，不自动重放文件修改或命令。
6. 实现路径失效、软件升级、资源移动/复制的再验证；更新当前位置，不改写原始日志。
7. 支持受控地自动保存已验证经验，并展示本次使用及新增记录。必要时提供显式的旧历史导入入口，限定来源、预算和可见性。
8. 依据实际漏召回案例评估语义检索；若增加模型依赖，单独记录成本、离线/缺失能力行为和索引版本。

### 5.3 放行条件

使用一个独立小型实验项目，完整执行：读取/修改代码 → 执行测试或实验 → 保存结果 → 退出 → 从另一目录恢复 → 找到结果和软件 → 完成后续分析 → 核对产物。

必须同时验证：

- 两个同名实验、两个相似结果目录和中文别名不会被无声混淆。
- 路径被移动、文件被外部修改、软件已升级时先核实，不能沿用失效事实执行副作用。
- 内容相同的复制文件不会无条件合并成同一资源。
- 原任务失败或取消时，已确认结果可用，未知操作先核实。
- 取消长命令后进程被清理、终端恢复，记忆只记录实际观察。
- 纯文本、JSONL、旧历史展示、全局选择器及安装升级仍正常。
- 对显式配置的 DeepSeek 和 OpenAI-compatible 分别记录真实结果；未配置 Provider 保持未执行。

### 5.4 停止条件

若助手只能回忆描述而找不到正确资源，或任务成功需要用户重新提供本应已保存的完整背景，需定位是记录、检索还是执行问题后再放行。未接入的 GUI 软件不得以文字演示代替实际跨软件验收。

## 6. L4：共享记忆与细粒度执行

### 6.1 目的与前置

在单助手闭环稳定后，支持多个助手共享指定知识并保留各自状态，落实与目录无关的资源动作授权。

### 6.2 开发工作

1. 增加助手作者、共享域、只读/可写记录范围和任务交接；基础记忆不自动暴露所有私有会话。
2. 逐记录版本检查与冲突处理；不同助手可以更新不同记录，同一事实冲突可见。
3. 区分文件读取、写入、删除、进程、网络和记忆复用等能力；完成可信配置到有效 grants 的转换。
4. 实现 Windows 驱动原型：专用低权限身份、受限令牌/ACL，按兼容性评估 AppContainer。安装时需要的系统配置与日常执行身份分开。
5. 文件工具和脚本子进程均进入真实执行边界；不能只有 Python 文件工具检查而 PowerShell 仍绕过。
6. 验证共享账户导致授权并集、继承句柄、链接目标、公共资源和工具链依赖；驱动声明不能落实的策略并拒绝相应执行。
7. 实现撤销：阻止后续检索/调用，处理正在运行的租约和进程，不宣称能收回已经读取的数据。
8. 保护凭据、记忆库和授权配置；模型请求所需凭据由可信宿主处理，不能把整库交给低权限工具进程。

### 6.3 放行条件

- 两个助手读取共同基础记忆，各自私有任务不泄露；共享写入冲突有可检查结果。
- 同一助手对 A 只读、对 B 可修改；文件工具、PowerShell、Python 以及子进程写 A 均被实际边界拒绝。
- 同时运行不同 grants 的两个任务，一个任务不能借另一个任务的账户权限扩大访问。
- 撤销来源授权后，新任务不能读取来源或召回受限派生记忆；进行中的操作按撤销语义停止或明确报告。
- 修改授权配置、直接访问凭据/完整记忆库的尝试被拒绝。
- 原生 Windows 中验证取消、超时、宿主崩溃的进程清理；Job Object 不被误记为文件隔离。
- 共享包、CLI、Web 身份映射及桌面打包输入一致；桌面最终构建和启动通过。

### 6.4 停止条件

隔离策略未落实、退回 current-user 却仍显示受限，或只有工具包装器测试通过时，不得宣称强隔离完成。完整多智能体审批组织、复杂委托链和跨设备同步不纳入此阶段，后续独立评审。

## 7. 数据与用户行为迁移

### 7.1 迁移约束

- 保留 `.agenthub` / `AGENTHUB_HOME`、profile、凭据引用、信任、session/Run ID、上下文和旧事件。
- 为旧 session 补充所属环境与保存位置；不把旧 root 当作永久身份，也不扩大旧信任。
- 新 schema 有最低兼容版本，旧二进制不能静默写新结构。每次阶段升级使用新的顺序迁移；具体编号在实现时与当前 schema 对齐。
- 迁移前获得迁移锁并检查活跃会话，忙时退出；通过 SQLite backup API 备份，覆盖 WAL 中已提交状态。
- 事务失败保留原数据和备份；回退旧 wheel 使用相应备份，明确不会包含升级后的新增记录。
- 旧日志不补造来源、作者或操作结果；无法确认的信息保留未知。
- 新记忆默认从明确写入和新工作积累；旧记录批量导入需显式范围，避免突然全局化所有历史。
- Web schema 变化通过 Alembic，Web 用户/环境映射独立；不把单用户 CLI 的环境默认值用于所有 Web 用户。

### 7.2 需要说明的行为变化

`-c` 从“当前目录最近任务”改为“本机环境最近任务”，恢复位置跟随任务。`sessions` 和 `/resume` 扩大候选范围，但目录筛选仍可使用。`/new` 不清空基础记忆；删除/遗忘记忆不默认删除 Run 历史。

发布说明应包含升级前后示例、只读检查入口、备份位置及故障恢复方法。已有原始验收记录不追溯改写。

### 9.2 比较方法

对相同项目、任务脚本和模型配置，比较关闭记忆、启用记忆和纠正后记忆三种条件。固定可检索记录的快照，说明任何外部文件变化与模型随机性，不预设 token 节省比例。

| 指标 | 观察方法 |
| --- | --- |
| 重复交代背景的次数 | 记录用户为找回工作额外提供的信息和轮次 |
| 找回正确工作的能力 | 固定候选集中正确选择/澄清/无结果；计入错误匹配 |
